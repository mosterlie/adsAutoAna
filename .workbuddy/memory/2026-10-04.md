## 亚马逊反爬实测结论（2026-10-04）
结论：搜索页 `/s?k=` 的边缘拦截**主要由请求头指纹触发**，与 HTTP 版本、UA、Cookie 无关。
受控实测（同一 URL，逐项加头）：
| 请求 | 结果 |
| curl 仅 UA | **503** |
| UA + Accept | 503（curl 默认已发 Accept，等于没变） |
| UA + `Accept-Encoding: gzip` | **200** |
| UA + `Accept-Language: ja-JP` | **200** |
| HTTP/1.1 vs HTTP/2 | 无差别 |
| 补齐头后 带/不带 Cookie | 均 200 |
| 商品页 `GET /dp/B01N9JG27P` | 200（商品页保护弱） |
503 响应头：`x-cache: Error from cloudfront`、`x-amz-cf-pop: NRT57-P5`、`server: Server`；body 是 Shift_JIS 的亚马逊通用错误页「ご迷惑をおかけしています！」(2153B) → 是亚马逊 CloudFront 边缘直接拒绝，非本地代理。
"接口"真相：亚马逊**无公开搜索 API**；抓包搜索页自身只发购物车相关 XHR，**搜索结果直接服务端渲染在 `/s?k=` 的 HTML 文档里**，没有独立 JSON 数据接口 → "从接口拉"本质就是拉该 HTML。
账号风险：调试 Chrome 内 amazon.co.jp 会话为**访客态**（cookie 仅 session-id/session-token/sst-acbjp/i18n-prefs/ubid-acbjp/lc-acbjp/csm-hit，**无 at-main/sess-at-main 登录令牌**）→ 不涉及买家/卖家账号。
缓解层次：头指纹(第一层) → IP/频率/行为风控 → 验证码。建议：保持浏览器方案、限频(≥几十秒/词)+随机抖动、不并发、不用登录态、遇 503/验证码熔断。当前项目已具备：30min 缓存 + 6s 最小间隔 + 全局串行锁。

## 异常体检结论（实测接口 + 核对DB，2026-10-04）
运行环境：依赖装在 /Library/Frameworks/Python.framework/Versions/3.11/bin/python3（managed 3.13 无 requests）。

已确认真实 Bug：
1. **数值排序失效**：指标字段在 raw_json 里是字符串（adCost='1936.57'），database.get_records 用 `ORDER BY json_extract(...)` 走文本序 → product.adCost desc 首位是 93.77 而非真实最大 1936.57。需 `CAST(... AS REAL)`。
2. **采集状态可能永久卡死**：crawler.run_crawl 取 Cookie 失败/init_db 失败时在 try 之前 raise，而 start_crawl_async 已置 STATE running=True，异常被 _work 的 except:pass 吞掉 → running 永远 True，后续采集全被挡，crawl_runs 残留 running。需把占位+异常也纳入 finally。
3. **SQL 注入面**：api.get_records 的 order_field 未校验，直接 f-string 拼进 `json_extract(raw_json,'$.{order_field}')`。
4. **netarget scope 维度丢失**：_scope_str 对 {adType,neType} 只取 adType → keyword/product 塌缩成同一 scope（当前账户 netarget=0，潜伏）。

已排除的“假异常”（重要修正，勿再当 bug 处理）：
- target 仅 3 条 = 正常。该账户 584 auto + 3 manual，关键词投放只存在于手动活动，3 个手动活动各 1 个 keyword target。

### 重要口径更正（2026-10-04）

- `searchKeyword`（queryType=`spQuery`）= **用户搜索词**，457 条 / 70 个活动，matchType=loose_match(239)/close_match(215)/exact(1)/substitutes(2)，有 searchFrequencyRank。**这才是严格意义的"搜索词"**。
- `searchAsin`（queryType=`spTargeting`）= **商品投放（Product Targeting）**，673 条 / 83 个活动，query 字段是竞品 ASIN，matchType=complements(288 互补商品)/substitutes(385 替代商品)，无 searchFrequencyRank。
- 故「合计 1130」= 搜索词条目 + 商品投放条目，**不是**"搜索词总数"。严格搜索词口径：457 行 / 413 个不同词串 / 覆盖 70 个活动（平均 6.5、中位 3）。
- 去重差异：同一活动同一搜索词在不同 matchType 下各占一行（15 个活动存在，如「ピックルボールネット」同时有 loose/close）。
- CSV 已重写为清晰口径列：搜索词条目数 / 搜索词去重数 / 商品投放ASIN数 / 条目合计 / 活动花费|曝光|点击|订单（后者是**活动级**指标，非搜索词行级）。
