## 搜索词与搜索 ASIN

**同一个接口，两个维度**：`POST gw:multiple/search/getAllSearchData`

```json
{"orderField": "impressions", "orderType": "desc", "shopIdList": ["711811"],
 "campaignIdList": ["90709676806138"], "adType": "sp",
 "searchQueryType": "searchKeyword",          // searchKeyword | searchAsin
 "statusList": ["enabled", "paused"], "servingStatusList": [],
 "startDate": "2026-11-08", "endDate": "2026-11-08",
 "pageNo": 1, "pageSize": 500, "fromSingle": true, "useAdvanced": false}
```

| 维度 | `searchQueryType` | `query` 是什么 | 额外字段 |
|---|---|---|---|
| 顾客搜的词 | `searchKeyword` | 真实搜索词 | `matchType`（`close_match` / `loose_match` / `complements`） |
| 广告出现的商品页 | `searchAsin` | 竞品的 ASIN | `price`、`asinRating`、`ratingCount` |

**两维度互补**：词维度看意图，ASIN 维度看竞争页。两者合计花费通常能覆盖 85%+ 的总花费（剩余为未归因）。

### 出单归因要看哪一个

一条转化的 `adOrderNum` 只会落在**其中一个维度**上。所以回答"这单从哪来的"，必须两个维度都查：

- 落在 `searchKeyword` → 顾客搜词进来
- 落在 `searchAsin` → 顾客在竞品详情页点进来（= 商品页面位）

> 实测 2026-11-08：两单全部落在 `searchAsin`（`substitutes` / `complements`），`searchKeyword` 0 单；
> 同时广告位数据显示 100% 在 `placementProductPage`。两个维度互相验证。

## ABA 搜索词排名

> ⭐ 这是这套接口里最有商业价值的一个。

```
POST https://www.sellfox.com/api/search/terms/analysis/getTrend.json
Content-Type: application/json
```

```json
{
  "marketplaceId": "A1VC38T7YXB528",
  "searchTerms": "チェストリグ######ラジオハーネス",
  "periodType": "WEEK",
  "startDate": "",
  "endDate": "",
  "departmentNames": "Amazon.co.jp######Amazon.co.jp"
}
```

### 三个必踩的坑

1. **多词用 `######`（6 个 #）连接**，不是逗号、不是数组
2. **`departmentNames` 必填，且数量必须与词数一一对应**（同样用 `######`）。少了就返回空
3. `startDate` / `endDate` 传**空串**（区间由 `periodType` 决定）

`periodType` 枚举：`DAY` / `WEEK` / `MONTH` / `QUARTER`

### 响应

```json
{"code": 0, "data": [{
  "searchTerm": "チェストリグ",
  "abaRank": "11000",
  "rank": null,
  "list": [{"startDate": "2026-08-02", "endDate": "2026-08-08",
            "searchFrequencyRank": 15007, "weekStr": "26年第32周"}]
}]}
```

| 字段 | 含义 |
|---|---|
| `abaRank` | 最新一期排名，**越小越热** |
| `list[]` | 历史趋势（周 13 期 / 月 12 期） |
| `weekStr` | 周维度才有；月维度是 `26年10月` |
| `rank` | 另一套排名（自然位），此处常为 null |

> **没有 ABA 记录的长尾词直接不返回**（不报错）。

> ⚠️ 不要用 `keywordLib/searchTermGetTrend`（新网关路径），**恒返回空**。

### 排名 ≠ 搜索量

排名是「全站搜索频次排名」。赛狐这条链路里**没有绝对搜索量字段**，要搜索量得走 ABA 后台导出或第三方工具。

### 分档（日站经验值，用于决定投放力度）

| ABA 排名 | 档位 | 策略 |
|---|---|---|
| < 10,000 | 极热 | 大词，严控 CPC |
| 10,000 – 50,000 | 中热 | 值得投，建议价上沿出价 |
| 50,000 – 200,000 | 长尾 | 低竞价养 |
| > 200,000 | 几乎无流量 | 慎重，或直接否定 |

## 建议关键词

`POST gw:adKeyword/sp/suggestKeywordsByAsin/page`

```json
{"shopId": "711811", "asinList": ["B0HQGMTCB3", "B0HQRVCQ88"], "pageNo": 1, "pageSize": 20}
```

返回 `data.keywordTypeList[{matchType, keywordText, keywordTextCn}]`，`data.totalSize` 实测 200。

> ⚠️ 字段名是 **`asinList`**（传 `asins` 报 `asinList: must not be null`）。
> 该接口**只给词、不给排名**，要排名得拿这些词去调 `getTrend` 补。

## 推荐建议竞价

`POST gw:multiple/target/suggestBid/recommendations`

```json
{"shopId": "711811",
 "asins": ["B0HQGMTCB3"],
 "placementProductPage": null, "placementTop": null, "placementRestOfSearch": null,
 "biddingStrategy": "AUTO_FOR_SALES",
 "targetingExpressions": [
   {"type": "KEYWORD_GROUP", "value": "keyword-group=\"category\""},
   {"type": "KEYWORD_GROUP", "value": "keyword-group=\"peerbrand\""},
   {"type": "KEYWORD_GROUP", "value": "keyword-group=\"gift\""},
   {"type": "KEYWORD_GROUP", "value": "keyword-group=\"brand\""}]}
```

- `targetingExpressions` 就是建活动时那 4 个 theme 群组
- `biddingStrategy` 与活动策略一致：`AUTO_FOR_SALES` / `LEGACY_FOR_SALES` / `MANUAL`
- 相比单投放的 `spTarget/getSuggestedBid`，这个**按 ASIN 批量**给价，适合建活动前估价

---

## 关键词群组（theme）是什么

建手动活动时 `matchType` 还有个值 `theme`，`keywordText` 是特殊标记：

| keywordText | 中文含义 |
|---|---|
| `keyword-group="category"` | 与商品类别相关的关键词 |
| `keyword-group="peerbrand"` | 顾客还会考虑的品牌 |
| `keyword-group="gift"` | 与礼物相关的关键词 |
| `keyword-group="brand"` | 与自己品牌相关的关键词 |

> theme 也会生成 target，但**响应里 `index` 顺序被打乱**（非 theme 在前、theme 4 条追加在尾部）。
> 回填 targetId 必须按 `index`，**不能按数组位置**。
