# 12 动作速查

> 这份是**接口 → 业务动作**的映射层：智能体与人都按「动作名」思考，不按接口路径思考。
> 机器可读版本在 `backend/ads_ops/actions.json`，本文是它的表格视图。

```bash
python3 -m backend.ads_ops.registry list              # 全部动作
python3 -m backend.ads_ops.registry show set_target_bid  # 单动作详情
python3 -m backend.ads_ops.registry search 调价        # 按意图找动作
python3 -m backend.ads_ops.registry describe          # 机器可读全量 JSON
```

级别含义：

| 级别 | 含义 | 执行策略 |
|---|---|---|
| **L1** | 单值可逆，改一个数字/状态，秒级回滚 | 可自动执行 |
| **L2** | 结构变更，增删对象，靠归档回滚 | 需报告 |
| **L3** | 新建 / 不可逆，非幂等 | **必须人工确认** |

## L3 · 新建 / 不可逆（2 个）

| 动作 | 用户常说 | 接口 | 编码 | 幂等 | 回滚 |
|---|---|---|---|---|---|
| `create_campaign` | 创建广告 / 新建活动 / 开个广告 | `gw:ad/sp/create` | JSON | ❌ | 归档（不可逆） |
| `archive_campaign` | 归档活动 / 下线这个广告 | `gw:spCampaign/archive` | form | ✅ | **无** |

`create_campaign` 的前置条件（缺一不可）：

1. 按 `name` 查重（赛狐禁止活动重名）
2. `products[].id` 用**产品库 id**（8 位）
3. 人工确认（非幂等，重试会产生重复活动）

## 按场景组合

### 「这个活动一天烧了 400 一分钱没出」

```
1. analyze  → 确认花费/订单/点击
2. set_target_bid     降 25%（4 个匹配位）
3. set_campaign_state 暂停（可选，看是否想留观察）
```

### 「这个活动出单了但要更多量」

```
1. analyze → 看 ACOS 与曝光
2. set_target_bid              +30%（4 个匹配位）
3. set_group_bid               同步组默认竞价
4. set_campaign_placement      商品页加价（若订单来自商品页）
```
> 注意先看 [03 广告位](03-读-广告表现.md#广告位) 的四位分布，**只加出单的那个位**。

### 「这个搜索词一直花钱不出单」

```
1. 算相关性（backend/term_relevance.py）
2. 相关性 ≥ 0.35 → 不否词，走人工排查价格/图片/评论
3. 相关性 < 0.35 且点击 ≥ 10 → add_negative_keyword
```

### 「把竞品页面成交变成可复制的入口」

```
1. 从 searchAsin 行找出出单的竞品 ASIN
2. create_campaign（手动商品投放，targetings=[{type:"asin", asin}])
3. 3 天后看是否出单，0 单则 archive_campaign
```
